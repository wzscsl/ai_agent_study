HITL Workflow
核心理念
Human-in-the-Loop高风险动作落盘前必须经过人工确认
把修改计划与真正写入拆成两个阶段
可用的 Agent 不是更自动，而是更可控
存在风险时，Agent 把执行权交还给人
关键链路
① 模型先生成修改计划（plan）
② ApprovalNode 展示目标文件、修改理由、将被替换的旧内容、准备写入的新内容
③ 只有明确输入 yes 才进入写入节点
④ 拒绝 → 终止写入，直接进入报告节点
强约束流程plan → approval → apply，缺一不可
新增节点
ApprovalNodeyes/y 批准；其他输入拒绝并可填写取消原因；summary 类任务自动跳过审批
SafeApplyNode硬约束：approval_required 且未批准 → 阻断写入；执行前先读文件做 before_snapshot 备份
HitlReportNode拒绝时报告“任务已取消”与原因；批准时汇总审批 + 执行 + 验证结果
上下文扩展
HitlWorkflowContexthitl_context.py：继承框架 HitlContext 与 CodeWorkflowContext
before_snapshot保存文件被修改之前的内容，便于回溯
框架 HitlContext 字段approval_required / approved / rejected / approval_note / human_feedback
复用关系
复用 demo8 Workflow 执行器与 Classify / Inspect / Plan / Verify 节点
