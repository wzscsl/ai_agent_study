demo6
最小 Agent 框架
设计目标
把 demo1–5 验证过的通用逻辑抽象出来
解耦：工具注册 / 消息存储 / 运行时循环分层
为 demo7 / demo8 / demo9 / demo11 复用打基础
五层抽象
模型调用层framework/llm.py · call_llm / ask_llm_json / ask_llm_text
工具注册层framework/tool_registry.py + decorators.py
消息存储层framework/message_store.py
Runtime 执行层framework/runtime.py · AgentRuntime 主循环
业务工具层builtin_tools.py · 具体文件工具实现
ToolRegistry 工具注册
register / register_many支持 ToolDefinition 或 @tool 装饰过的函数
register_tools_from_module()传入模块即批量注册所有 @tool 函数
build_tools_payload()把 Python 工具定义翻译成 LLM 的 tools 格式
execute_tool_call()JSON 参数解析 + 未知工具 / 参数不匹配等错误兜底
@tool 装饰器
函数签名 + 类型注解 → 自动生成 JSON Schema
工具定义挂在函数的 __tool_definition__ 属性上
可覆盖 name / description / parameter_descriptions
收益工具函数本身就是工具定义，少写重复 schema
MessageStore 消息存储
append / extend统一写入入口，写入即自动裁剪
trim()按 max_turns × 4 条消息估算，保留最近若干轮
snapshot()返回当前消息快照给运行时组装请求
AgentRuntime 主循环
create_state()goal + shared_context 通用状态，不写死业务字段
消息组装三段式system → 历史消息 → 本轮运行时状态调度消息
context_updates工具返回的上下文自动合并进 shared_context
on_tool_result()可覆写的扩展钩子，供子类定制（demo7 会用到）
超过 max_loops → 抛 RuntimeError 终止
组装与练习
create_runtime(...)helpers.py 一键装配 Runtime + MessageStore
framework_demo.py入口示例：注册 builtin_tools 并运行一个任务
练习新增自己的 @tool / 收紧循环次数限制 / 替换 Store 与 Registry 实现观察影响
