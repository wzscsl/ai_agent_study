demo8
Workflow Agent
核心理念
任务拆成固定节点，节点通过 action 决定下一跳
节点职责单一，更适合扩展与调试
适合需要稳定步骤、清晰审计链路的任务
框架层 framework/
Workflow最小执行器：执行节点 → 读取 action → 跳转下一跳；max_steps 防死循环
BaseWorkflowNoderun() 执行当前节点；connect(action, node) / route(action) 管理路由
WorkflowContextgoal + shared 共享字典 + logs 执行日志
HitlContext带人工打断字段的上下文（demo9 复用）
六大节点 nodes.py
ClassifyNodeLLM 输出 JSON：intent(summary/edit)、target_file、search_query、reason
InspectNode列目录 + 关键字搜索 + 目标文件快照
PlanNode收敛为精确 patch plan：old_text / new_text / expected_occurrences / rationale
ApplyNode有 old/new 则替换，否则整文件写入
VerifyNode读回文件，确认变更结果
ReportNode汇总日志与结果，生成用户可读的中文总结
路由拓扑
classify → inspect
inspect → plan（edit 修改类）/ → report（summary 总结类）
plan → apply → verify → report
action == "done" → workflow 结束
分层设计
框架能力（workflow / node / context）与业务节点（nodes.py）分离
复用 demo6：ask_llm_json / ask_llm_text
tools.py文件观察与修改工具（list / search / read / replace / write）
workflow_demo.py入口：build_workflow() 串联节点并循环接收目标
对比与练习
demo7 自由循环 → demo8 显式节点、可预测流程
练习：新增一个节点（如 risk check）
练习：同一任务对比“自由 agent”与“固定 workflow”
练习：让 VerifyNode 多做一步结果总结
