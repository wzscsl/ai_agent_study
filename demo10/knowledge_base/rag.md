# RAG

RAG 是 Retrieval-Augmented Generation，检索增强生成。它的核心思想是：模型回答问题之前，先从外部知识库里检索相关资料，把资料放进 prompt，再让模型基于资料生成答案。

## 为什么需要 RAG

大模型的知识冻结在训练截止日期，而且没有见过私有数据。直接问它内部文档的细节，它很容易凭空编造。RAG 通过"先检索、再生成"，把回答的事实依据从模型参数转移到了外部资料上，显著降低幻觉概率。

## RAG 的完整链路

一次完整的 RAG 包含六个步骤：加载文档、切分 chunk、向量化、写入向量数据库、相似度检索、生成答案。

切分时 chunk 太大会导致检索不精准，太小会割裂语义，通常用 overlap 让相邻 chunk 保留衔接。检索时把用户问题和文档都转成向量，用余弦相似度找最接近的 Top-K 条资料。

## 智谱 embedding-3

demo 里向量化使用智谱的 embedding-3 模型，它默认输出 2048 维的向量。查询文本和文档必须使用同一个 embedding 模型，因为不同模型的向量空间不可比较。

## RAG 和微调怎么选

RAG 改变的是"模型这一轮能看到什么"，微调改变的是"模型本身"。知识频繁更新、需要溯源、涉及私有数据时优先 RAG；需要改变模型风格或领域行为时考虑微调。两者可以叠加使用：先微调让模型更懂领域，再用 RAG 补充实时事实。

## RAG 在 Agent 里的位置

RAG 给 Agent 提供外部记忆，回答"知道什么"；工具调用给 Agent 提供外部动作，回答"能做什么"。把检索注册成 Agent 的一个工具，让模型自主决定何时查库，是 RAG 和 Agent 的自然结合方式。
