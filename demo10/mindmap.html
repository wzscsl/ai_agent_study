demo10
RAG Agent
核心理念
先检索、再生成Retrieve → Generate，而不是只靠上下文窗口
外部知识库显著降低“凭空编造”的概率
查询与文档必须用同一个 embedding 模型才能处在同一个向量空间
六步链路
① load_knowledge_base()读取 knowledge_base 下的 Markdown 文档
② split_text()按 CHUNK_SIZE=700 / CHUNK_OVERLAP=120 切块
③ embed_texts()调用智谱 embedding-3 生成 2048 维向量
④ rebuild_index()初始化 pgvector 表 rag_chunks 并写入索引
⑤ retrieve()问题向量化，相似度检索取 Top-K=4
⑥ answer_with_rag()资料拼进 prompt，交给 LLM 生成答案
模块划分
rag_demo.py入口：先建索引，再进入多轮问答循环
document_loader.py加载文档 + 切分 + md5 生成 chunk_id
embeddings.pyembed_texts / embed_query 统一向量化
rag_store.py连接数据库、建表、写入向量、相似度检索
config.py维度、表名、TOP_K、CHUNK 等配置集中管理
技术栈
DeepSeek生成最终答案的大模型
智谱 embedding-3文本向量化模型
PostgreSQL + pgvector向量存储与相似度检索（如阿里云 RDS）
psycopgPython 数据库驱动
检索细节
RetrievedChunksource / chunk_index / content / distance
vector_literal()把 list 转成 pgvector 文本格式 [0.1,0.2,...]，参数化传入防注入
按 distance 升序取 Top-K 相关 chunks
build_context_text()检索结果带来源与距离编号，整理成 prompt 上下文
Prompt 约束与知识库
回答必须优先依据提供的资料
资料里没有答案 → 明确说资料不足，不编造
示例知识库agent_basics.md / react.md / workflow.md / hitl.md
练习
新增一篇知识库文档，观察检索与回答变化
调整 chunk 大小 / overlap / Top-K，比较召回质量
故意问知识库里没有的问题，看是否如实说明资料不足
