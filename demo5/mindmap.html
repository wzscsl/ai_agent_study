demo5
ReAct Agent
本节目标
理解 ReAct 如何在灵活性与可控性之间找平衡
学会同时维护 messages 和结构化 state
看懂带多工具、多轮观察的 Agent 主循环
文件结构
react_demo.py程序入口：多轮对话循环，输入 exit / quit 结束
agent.pyrun_react_agent() 主循环 + 消息组装与裁剪
tools.py工具定义 build_tools() 与执行 execute_tool_call()
state.pycreate_agent_state() / update_state_from_tool_result()
llm.py / config.py模型调用、API Key、循环次数与历史轮数配置
核心机制
run_react_agent()程序不再写死下一步，模型根据上下文自行决定是否继续调用工具
build_runtime_messages()system 消息 + 任务状态摘要 + 裁剪后的历史 messages
update_state_from_tool_result()把最近一次工具结果同步进 state，形成观察反哺
trim_messages()只保留最近 MAX_HISTORY_TURNS 轮（每轮约 4 条消息）
双状态设计
messages给模型看：会话记忆 + assistant/tool 消息历史
state给程序判断：结构化任务事实
state 字段current_goal / last_tool_name / last_created_path / last_read_content / completed / loop_count
内置工具
create_text_file创建文本文件（从单一写文件扩展而来）
read_text_file读取文件内容，供模型自我检查
list_files列出生成目录中的文件
主循环流程
① 组装消息并调用 LLM（携带 tools payload）
② 返回 tool_calls → 先写入 assistant 意图消息
③ 逐个执行工具 → 结果写回 role=tool 消息并同步 state
④ continue 进入下一轮，再次观察再决策
⑤ 无 tool_calls → 自然语言答复，completed=True
超过 MAX_AGENT_LOOPS → 抛错终止，建议细化任务重试
学习要点
demo4 显式状态机 → demo5 自由循环式 Agent
结构没有消失，而是藏进运行时与状态里
练习生成文件后再读出检查 / 列出文件再修改总结 / 新增一个工具验证主循环稳定性
运行方式python demo5/react_demo.py
